# Bounded real mGBA integration test

This test is prepared, not a runtime pass. Read `artifacts/native/mgba/result.json`
from a run of the **exact source commit** before reporting an outcome. A skipped
Windows test, green packaging job, process spawn, changing window title, or
screenshot by itself is not evidence that the game/foreground checks passed.

## Official binary and CI insertion

mGBA's [official downloads](https://mgba.io/downloads.html) identified **0.10.5**
as current when checked on 2026-10-02. Use the pinned Windows x64 portable asset,
not an installer, unofficial mirror or floating `latest` URL. The following step
belongs in `.github/workflows/verify.yml`'s existing Windows `package` job, after
`npm ci` and the ordinary desktop smoke, before the existing native-artifact
upload. No additional npm package, third-party ROM, BIOS or admin change is needed.
The runner's included 7-Zip extracts the archive; no emulator files are committed
or added to the Renew package.

```yaml
      - name: Prepare official mGBA 0.10.5
        shell: pwsh
        run: |
          $ErrorActionPreference = 'Stop'
          $root = Join-Path $env:RUNNER_TEMP 'renew-mgba-official-0.10.5'
          New-Item -ItemType Directory -Path $root -Force | Out-Null
          $archive = Join-Path $root 'mGBA-0.10.5-win64.7z'
          $url = 'https://github.com/mgba-emu/mgba/releases/download/0.10.5/mGBA-0.10.5-win64.7z'
          Invoke-WebRequest -Uri $url -OutFile $archive
          $digest = (Get-FileHash -Algorithm SHA256 $archive).Hash.ToLowerInvariant()
          $extracted = Join-Path $root 'extracted'
          & 7z x $archive "-o$extracted" -y
          if ($LASTEXITCODE -ne 0) { throw 'Official mGBA extraction failed.' }
          $executables = @(Get-ChildItem -LiteralPath $extracted -Recurse -File -Filter mGBA.exe)
          if ($executables.Count -ne 1) { throw 'Expected exactly one official mGBA.exe.' }
          "RENEW_MGBA_EXE=$($executables[0].FullName)" >> $env:GITHUB_ENV
          "RENEW_MGBA_ARCHIVE_SHA256=$digest" >> $env:GITHUB_ENV
      - name: Real mGBA integration and foreground evidence
        run: node --test tests/native/mgba-integration.test.cjs
```

The existing `if: always()` upload of `artifacts/native/` also captures this test's
JSON and screenshots when it fails or is blocked. Keep the CI job timeout (20
minutes is sufficient); the test body has a three-minute timeout, with separate
bounded cleanup waits. A four-minute workflow-step timeout supplies an external
budget even if the native runtime stops responding. The recorded archive digest is a provenance receipt, not a claim of
independent checksum authentication. The download trust boundary is the pinned
release asset linked by the official project. Review the actual download step,
commit and receipt together.

To run in an already-authorized isolated Windows test environment, extract that
same official archive, set `RENEW_MGBA_EXE` to its full executable path and run the
same Node command from the repository root after `npm ci`. Do not run the probe
on a personal/shared desktop without authorization: its screenshots capture the
emulator's visible screen rectangle. Use one isolated test at a time.

## What actually runs

- The unchanged Electron entry point, preload, trusted IPC, `LauncherService`
  and `MGBASession`; Play is clicked in Renew. No process mocks or replacement
  launcher are used
- Real services seed a temporary library. This deliberately does not test the
  native file-picker interaction
- The official executable and accompanying files are copied into a unique
  temporary directory. mGBA's supported `portable.ini` marker isolates its
  configuration; Renew has its own temporary `userData`
- A 1 KiB original GBA program is generated by
  `tests/native/fixtures/renew-smoke-rom.cjs`. Its Nintendo-logo region is all
  zero. It contains no external ROM, BIOS, assets, runtime or compiler output.
  It displays red, green and blue frames, changing every 30 emulated VBlanks
- The PowerShell helper observes the Windows session, input desktop,
  `GetForegroundWindow`, exact executable path, parent PID, command line,
  title, visibility, minimized state and monitor/window bounds. Renew is identified
  by Electron main-process `process.pid` and its exact
  `BrowserWindow.getNativeWindowHandle()`; user32 verifies that HWND owner and
  its foreground/visibility state. The launch-wrapper PID, Electron startup
  visibility and every raw pre-Play sample are retained for attribution
- Screen pixels must show all three expected ROM colors while the real mGBA
  title identifies `RENEW SMOKE` and version 0.10.5, mGBA owns OS foreground,
  its captionless window fills a monitor and Renew is minimized
- A normal `WM_CLOSE` goes only to this test's owned mGBA window. A pass requires
  process exit, a clean app session result, Renew restored to OS foreground and
  play time persisted. Forced cleanup is never accepted as exit/return evidence

Launch/session, ROM identity, fullscreen/foreground, animated pixels, and normal
exit/return/persistence have separate receipt fields. A color mismatch is reported
only after attempting normal close and measuring return, so a fixture/rendering
problem does not erase independent return evidence. The full test still fails
unless all required observations pass.

## Interpreting results

- `PASS`: all bounded real-emulator, actual-pixel and foreground checks passed
  on that Windows runner for those source hashes
- `FAIL`: a required observation/assertion failed; inspect its error, samples
  and screenshots. An unexpected missing dependency is a failure, not a skip
- `BLOCKED`: no usable interactive Default desktop, Renew could not establish
  its natural foreground baseline, or the foreground desktop disappeared.
  Node reports this as a skip, so a green job can still leave this gate unmeasured

The harness does not change session/security policy, switch desktops, activate
windows forcibly, inject OS clicks/keys, attach input threads or make windows
always-on-top. If the hosted runner has no usable foreground desktop, keep that
part blocked and use an authorized interactive Windows test environment later.
Do not force a foreground pass on a service/headless session.

Each native observation/action is a separate 15-second-bounded PowerShell
invocation with a base64 JSON argument; no persistent stdin/RPC pipe is used.
Short stderr phase markers are saved with successful samples and included in
timeout/error details. An explicit Electron HWND bypasses the redundant .NET
`MainWindowHandle` lookup; its user32 owner/foreground checks remain mandatory.

The JSON receipt is checkpointed at each phase and before cleanup starts, so a
timeout retains the last observation. Electron close has an explicit deadline;
last-resort `app.exit(1)` requires the connected main PID and isolated user-data
path to match. Any forced emulator/app termination marks the run `FAIL`. The
launch wrapper is tracked separately and its exit does not prove Electron exited.
Constructed and `fs.realpath` canonical emulator/ROM paths are recorded to avoid
confusing Windows short-path aliases with a different file.

Temporary cleanup targets only the test-created files and exact unique emulator
path, plus its own Electron/probe processes. On an unconfirmed cleanup error the
temporary tree is retained for diagnosis.

This does **not** establish physical-PC behavior, audio/controller input,
commercial-game compatibility, installer/portable-package boot, high-DPI or
multi-monitor behavior. The remaining manual gate in `VERIFICATION.md` still
applies. The test does not require a proprietary BIOS and its fixture is not a
claim of physical-hardware boot compatibility.
